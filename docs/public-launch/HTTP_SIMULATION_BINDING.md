`SimulationHTTPBinding` attaches the explicit simulation policy to the existing request database dependency and supplies a per-application analysis runtime. It retains normal authentication and session handling, validates the current owner/environment before returning a runtime, clears bindings on teardown, and refuses replacement of existing runtime/database/disposable-service bindings. It registers no global runtime and mounts no routes. Tests use actual analysis/source/list handlers against disposable SQLite for both simulated owners, plus an invalid owner and binding collisions.

`synthetic_connections.connect` creates credential-free fake connections in either Kite app mode. Requests carry an expected current connection identity/version and an owner-scoped idempotency key. Owner serialization and the existing unique-current index protect replacement. Prior rows retain their immutable binding details for later reconciliation; new rows contain no credential reference. Existing real/legacy or credential-bearing rows require a separate reviewed migration and are denied before replacement. This code performs no provider call and grants no financial authority or provider approval. It is an internal service; no HTTP mutation route is installed yet.
