Implementation began 2026-10-23 21:20 UTC; retained verification finished 21:23 UTC. This follows local HTTP/connection candidate 13e0c39e9a7155f08f20467596e0e23af1a41528.

Hosted `SyntheticAnalysis` now requires its explicit journal source adapter. The existing daily Zerodha snapshot path remains the default for the disposable preview and is not changed for live acquisition. The journal uses an undispatched evidence topic in the existing SQL outbox, not another database, model, resource or migration. Each bounded immutable receipt binds its owner, server-fixed synthetic holdings, capture, exact current credential-free fake connection identity/version/mode, hashes and scoped request key. Canonical module authorization retains the owner selection lock through the acquisition transaction. Reads never acquire, repair or relabel source data.

Reconnection preserves prior connection and source rows. Reusing the old source key after a connection change fails closed; explicit acquisition under a new key produces new provenance on the same day. New acquisition invalidates old active workflow input hashes. This avoids overwriting the daily snapshot or blessing a legacy snapshot. Source history is bounded at 4096 records per owner and refuses further acquisition pending reviewed retention rather than deleting evidence.

The authenticated source action accepts an optional typed key for existing preview compatibility; journal acquisition requires it. The HTTP and worker compositions select the same source adapter. Hosted callers cannot select the legacy snapshot adapter. The journal can be explicitly selected only by server construction for disposable testing; request bodies cannot select scope, adapter, owner, holdings or connection facts.
